§1基础概念

术语定义类比 / 备注
认证Authentication · AuthN 确认「你是谁」。 大门口刷工牌、人脸核验。0001
授权Authorization · AuthZ 决定「你能做什么」。总在认证之后发生。 工牌能开研发区、开不了财务室。0001
认证因素Factor / Credential 用来证明身份的东西：密码、验证码、指纹等。 见 认证方式①。0001
无状态Stateless HTTP 协议处理完一次请求就「忘了」你，两次请求之间没有记忆。 所以才需要 Session + Cookie。0001
会话Session 服务器端保存的「此用户已登录」记录，以 Session ID 为索引。 前台的访客登记本。0001
CookieHTTP Cookie 服务器让浏览器保存的一小段数据，之后访问同一域名时浏览器自动携带。常用来存 Session ID。受域名隔离：不能跨不同主域名共享。 前台发的访客号码牌。0001

§2SSO 角色与机制

术语定义类比 / 备注
单点登录SSO · Single Sign-On 登录一次，即可访问多个互相信任的应用。 一张工牌刷遍全公司。0001
IdP（认证中心）Identity Provider 专门负责认证用户、签发认证凭证的服务。全体系只有它核对密码。 CAS Server、Keycloak、Okta、Azure AD（Entra ID）都是 IdP。0001
业务应用SP · Service Provider 依赖 IdP 认证结果的应用（OA、Wiki、CRM…）。不接触密码，只验证认证凭证。 各协议叫法不同，见对照表。0001
认证凭证Security Token (泛称) IdP 签发给应用、证明「此用户已在 IdP 认证」的东西。三大协议的核心差异就在它的形态与验证方式。 CAS = 票据；SAML = 断言；OIDC = ID Token。0001
重定向HTTP 302 Redirect 服务器响应「请去另一个网址」，浏览器自动跳转。是动作、是交通工具。SSO 流程中共发生两次：① 应用把你送往 IdP；② 认证后 IdP 把你送回应用（目的地就是回调地址）。 SSO 流程的「交通工具」。0002
回调地址Callback / Redirect URI IdP 认证完成后把用户送回应用的地址。是地址、是目的地，即第二次重定向要去的地方。第一次重定向时它作为参数告知 IdP；必须事先在 IdP 登记，否则拒绝（防止凭证被送到攻击者网站）。 CAS 叫 service，OIDC 叫 redirect_uri，SAML 叫 ACS。集成时最常见的报错来源之一。0002
单点登出SLO · Single Log-Out 在一处退出，所有已登录应用一起退出。 比单点登录难做得多。0003

§4CAS 专有术语

术语定义备注
TGTTicket-Granting Ticket 用户在 CAS 登录成功后，CAS 服务端创建的全局登录记录，代表 SSO 会话本身。 「发票据的票据」。0003
TGCTicket-Granting Cookie 浏览器中指向 TGT 的 Cookie，只发给 CAS 服务器。第二个应用免密登录就靠它。 0003
STService Ticket CAS 签发给某个应用的一次性票据，经 URL 参数传给应用。 用完即废，且有效期很短。0003
票据校验接口/serviceValidate 应用拿 ST 去 CAS 后台核验真伪、换取用户名。CAS 3.0 为 /p3/serviceValidate，可返回用户属性。 0003

§5SAML 专有术语

术语定义备注
断言Assertion IdP 签发、带数字签名的 XML 文档，声明「此用户已认证」并携带属性（邮箱、部门等）。 0004
认证请求AuthnRequest SP 发给 IdP 的 XML 请求：「请帮我认证这个用户」。 0004
元数据Metadata 双方互换的 XML 配置文件：实体 ID、端点地址、签名证书。集成 SAML 的第一步就是交换元数据。 0004
ACSAssertion Consumer Service SP 上接收断言的端点地址（SAML 版的回调地址）。 0004
NameID 断言中标识用户的字段，如邮箱或工号。 0004
SP 发起 / IdP 发起SP- / IdP-initiated 流程从应用开始（访问应用 → 跳 IdP），或从 IdP 门户点击应用图标开始。 0004

§6OIDC / OAuth 专有术语

术语定义备注
OAuth 2.0 授权框架：让第三方应用在用户许可下访问其资源。本身不定义「用户是谁」。 RFC 6749 标题即 Authorization Framework。0005
OIDCOpenID Connect 建立在 OAuth 2.0 之上的身份层，用 ID Token 补上「认证」。 0005
ID Token OIDC 签发的 JWT，内容是「谁、何时、被哪个 IdP 认证、给哪个应用」。给应用看的。 0005
Access Token OAuth 的访问令牌，用于调用 API。给资源服务器看的，应用不应用它判断用户身份。 与 ID Token 的区别是高频考点。0005
JWTJSON Web Token 三段式签名令牌格式：Header.Payload.Signature，Base64URL 编码。 编码 ≠ 加密：任何人都能解码看到内容。0005
授权码Authorization Code 授权码流程中 IdP 返回的一次性中间码，应用后端用它换取 Token。 Web 应用的推荐流程。0005
JWKSJSON Web Key Set IdP 公布公钥的接口，应用用这些公钥验证 ID Token 签名。 0005
Scope 申请的权限范围。OIDC 请求必须包含 openid。 0005

§7认证方式①：认证因素（用什么证明你是你）

类别例子备注
知识因素Something you know 密码、PIN 码、安全问题 最普遍，也最容易被钓鱼、撞库。
持有因素Something you have 短信验证码、TOTP 动态码（如 Google Authenticator）、硬件安全密钥（如 YubiKey）、客户端证书 证明你拿着某个设备。
生物因素Something you are 指纹、人脸、虹膜 通常在本地设备上比对。
多因素认证MFA 组合 ≥ 2 种不同类别的因素。 密码 + 短信码 = MFA；密码 + 安全问题 ≠ MFA（同属知识因素）。
通行密钥Passkey · FIDO2 / WebAuthn 基于公私钥的无密码登录：私钥留在设备里，配合指纹/人脸解锁。 天然防钓鱼，是当下的发展方向。

§8认证方式②：技术机制（系统如何传递与验证身份）

机制原理一句话典型场景
HTTP BasicBasic Auth 每次请求头携带 Authorization: Basic base64(用户名:密码)。Base64 不是加密，必须配合 HTTPS。 内部工具、简单 API
Session + Cookie 服务端存会话，浏览器带 Session ID。 传统单体 Web 应用
Token（如 JWT） 服务端签发自包含的签名令牌，客户端放在 Authorization: Bearer …，服务端验签即可，不必存会话。 前后端分离、移动端、微服务
API Key 给程序（而非人）用的长期密钥，随请求发送。 开放平台、服务间调用
双向 TLSmTLS / 客户端证书 不只服务器出示证书，客户端也出示证书。 服务间通信、高安全内网
LDAP / AD 企业目录服务，存放账号与密码。应用或 IdP 通过它核对密码。不是 SSO 协议，常作为 IdP 背后的用户数据源。 企业账号体系
Kerberos 基于票据的网络认证协议，Windows 域登录的核心。 企业内网 SSO
SSO 协议CAS · SAML · OIDC 把认证交给 IdP，跨应用共享登录状态。 多系统统一登录 ← 本课程主线
