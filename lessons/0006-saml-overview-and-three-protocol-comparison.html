SAML 速览与三协议大总结

认识第三门语言，然后把整门课程装进一张表。

约 10 分钟 前置：第 5 课 速查：术语表

SAML 是三巨头里资历最老的（2005 年 OASIS 标准）。你们大概率不用亲手对接它，但有两个理由值得花十分钟认识：第一，你们当前「PF + OpenToken 的 SAML 联合登录」里，SAML 正是联邦环节的幕后语言——看懂它，自家系统的说明书就通读了一遍；第二，老牌企业 SaaS 至今遍地 SAML——读懂它，公司里任何登录体系你都叫得出名字。

§1SAML 30 秒定位

维度SAML 2.0
角色叫法认证中心 = IdP；业务应用 = SP（Service Provider）——「IdP」这个词的成名地
认证凭证断言（Assertion）：一段带数字签名的 XML，声明「此用户已认证」并携带属性
验证方式SP 用 IdP 证书本地验签（和 OIDC 同思路，比 CAS 早了快十年）
配置方式双方交换元数据（Metadata）XML：实体 ID、端点地址、证书——SAML 版的「登记白名单」

按 OASIS 官方技术概览的说法，断言里装的是「断言方声称关于某个主体为真的声明」——具体分三类：认证声明（用户何时如何登录）、属性声明（邮箱、部门、工号）、授权决策声明（少用）。

§2SP 发起流程：一图流

图 1 · SP-Initiated SSO（对照第 2、4 课的图看，骨架一模一样）
1
浏览器 ──▶ SP：访问应用，无本地会话 熟悉的开场
2
SP ──302──▶ 浏览器 ──▶ IdP【第一次重定向】：携带 AuthnRequest（「请帮我认证这个用户」） 相当于 CAS 的 service 参数、OIDC 的 redirect_uri —— 都是在说「我是谁、送回哪」
3
浏览器 ──▶ IdP：无会话 → 出登录页输密码；有会话 → 免密直通 每个协议都有自己的「TGC」戏码
4
IdP ──302──▶ 浏览器 ──▶ SP【第二次重定向】：把签好名的 XML 断言送到 SP 的 ACS 端点（回调地址） 注意：XML 体积大，SAML 常用POST 表单提交而非 URL 参数——这是它与 CAS/OIDC 的一个外观差异
5
SP（内部）：用 IdP 证书本地验签断言 → 取出 NameID（用户标识）与属性 不回 IdP 查询——这就是「签名代替查询」，和 OIDC 一个哲学
6
SP：建本地会话 → 登录完成 三课三个流程，结尾永远这一步

SP 发起 vs IdP 发起 上面是 SP 发起（用户先访问应用）。SAML 还有个特有变体：IdP 发起——用户从 IdP 的应用门户点图标进入应用，IdP 直接推送断言过去。日常排错时先分清是哪种发起，日志位置完全不同。

§3三协议大总结

维度CASSAML 2.0OIDC
诞生2001 · 耶鲁 → Apereo2005 · OASIS2014 · OpenID 基金会（基于 2012 的 OAuth 2.0）
认证凭证ST 票据（随机串）XML 断言（签名）ID Token = JWT（签名）
应用如何验证回后台查询 /serviceValidate本地验签（证书）本地验签（JWKS 公钥）
回调地址叫serviceACSredirect_uri
防重放/防伪造ST 一次性 + service 绑定签名 + Conditions（时效/受众）签名 + state + nonce + PKCE
配置体验简单（URL 参数）重（双份 XML 元数据）最好（发现端点自描述）
典型场景高校、政企内网老牌企业 SaaS现代 Web / 移动 / 云原生
你们的角色现在时：应用正在用可能在 CAS↔PF 链路幕后将来时：迁移目标

最后回望第 1 课的通用骨架——跳到认证中心 → 登录（或被会话 Cookie 免密放行）→ 带一次性凭证回来 → 验证凭证 → 建本地会话。三个协议六课内容，兜兜转转全是这一个骨架的变奏。你现在拥有的是「骨架眼睛」：任何登录体系，先找两次重定向，再问「凭证是什么、谁验证」，它对你就是透明的。

课程总结

  1. 一个骨架：跳转 → 登录/免密 → 带一次性凭证回 → 验证 → 建本地会话。三协议皆此骨架的变奏。
  2. 一个原则：认证只发生在一处（你们的 PF）；Cookie 域名隔离不是障碍，是 SSO 的机制本身。
  3. 一套方法论：先找两次重定向，再问「凭证是什么、谁验证、怎么防伪」——任何登录体系皆可拆解。
  4. 一份行动方案：第 5 课七步清单 + 坑点表，就是你们 OpenToken → OIDC → 自研 IdP 两段迁移的起点。
